# Real2Sim Prompt v0

分两步处理 Real2Sim：**第一步，真实视频 → Blender 场景与动作；第二步，Blender → MuJoCo 场景与实际物理执行。** 两步共用源索引、交互关键帧、坐标与参数来源记录。默认追求**可用的交互重建**；先让目标、相机方向、相对位置和操作过程可辨认，再按任务需要提高精度。用户认可的质量是当前项目的验收依据，不因仍有差异而无限返工。

## 先确定本轮范围与验收等级

沿用已选场景、版本、数据、相机、阈值和用户授权。续做时先读最新交付清单、接受记录与未关闭问题，定位当前工程；不重新探索整个仓库。

完整流程包含两步；用户只要求 Blender 建模/视频时完成第一步，只要求模型导入或诊断时在对应范围交付。输入已有合格 `.blend` 可直接进入第二步。第一步的画面认可不等于第二步的物理任务成功；用户要求走通实际物理执行时，不能停在模型加载或状态回放。

- **默认：可用重建**。主要物体、机器人连接与交互关系合理，视角和源帧对应正确，无影响任务的明显穿入、断裂或跳变。背景布局、非关键纹理、光照和细小轮廓偏差可带说明通过。
- **精确对齐**：用户要求定量几何、时序或接触精度时，按已约定指标评测任务区域。没有约定容差时，依据用途设定并记录，不把“任何非零误差”都当失败。
- **高保真/研究验证**：仅在明确需要时增加完整相机标注、精细外观、实测动力学辨识或连续检测等成本。可用重建不默认升级到此等级。

用户明确接受某版本时，记录场景哈希、接受范围、已知偏差与依据，停止追究已接受的非阻塞项。保留历史测量，不能把用户接受改写为测量误差为零；单场景的容差不能推广为通用阈值。

## 第一步：真实视频 → Blender 场景与动作

### P0—P3：建立或恢复可检查场景

1. **数据与索引**：确认全部视角、共同帧范围、坐标/单位、时间戳与机器人状态。保持源帧、Blender帧、视频帧的映射；区分实测、拟合、插值和模拟。播放帧率不冒充采集速率。
2. **机器人与相机**：使用当前硬件的URDF或等效结构，处理visual/collision的origin、axis、scale、limit及mimic。保留结构节点和安装件，检查FK与可见连接。静态/腕部相机采用各自的逐帧模型。
3. **物体与场景**：先拟合操作区的尺度、形状、相对位置与材质；容器保留杯底、薄壁和空腔。背景做到能解释视角和支撑即可，不默认逐个复制无关陈设。
4. **基线检查**：首次建立场景时检查全场景的完整性、支撑和操作区碰撞。已验证的资产与静态环境可复用；局部更新只使相关检查失效，不无条件重建基线。

实测关节与标定不得为视觉对齐被无记录改写。工具抓取偏差先查安装变换、URDF导入、工具尺度和物体姿态。碰到具体结构/接触问题时才读[工程排查与增量验证](references/engineering.md)。

### P4：交互关键帧与五问

按接近后首触、稳定抓持、离开支撑、离开容器、进入另一容器、放置、松开及完全分离等**关系变化**取帧，并保留起止参考。真实与仿真事件时间分别记录；遮挡下的代表帧不是精确首触真值。新增异常交互补入事件表，不以固定帧数作为完成条件。

每个关键帧、每个可用视角保留五问。默认每问一句具体结论，按任务区域判断：

|问题|默认可用重建的判断|
|---|---|
|① 最大差异是什么？|描述差异及是否影响本轮目标。这是观察项，不因“发现差异”自动失败。|
|② 同帧相机视角是否对齐？|相机身份、源索引、主要朝向和操作区投影相符即可带说明通过；背景未复刻不自动归因于相机错误。|
|③ 物体相对位置是否一致？|目标间前后/左右/上下、尺度级别、遮挡、夹持部位和交互阶段合理；影响抓取或落点的偏差才优先修复。|
|④ 是否存在穿模？|区分正常接触、二维遮挡和实体穿入，结合几何检测及已记录容差。真实RGB不能提供未经测量的三维穿透深度。|
|⑤ 逼真度是否足够？|按用途判断目标形状、动作、接触和结果是否易辨认。可用重建允许材质、光照、背景和小细节近似；不默认要求照片级。|

状态采用 `pass / pass_with_notes / fail / review`；①可用 `observed`。`fail`仅用于超出当前等级的阻塞问题。单视角遮挡可保留该视角`review`，由其他视角和几何证据支撑事件通过；不要为了消除不可观测项反复渲染。用户认可的已知差异用`pass_with_notes`记录，不继续一票否决。

首次建立每帧五问基线；后续记录本轮实际变化，未受影响项引用同版本依赖有效的旧记录。可以生成完整表格，但不要让模型重复撰写不变的225段解释。不能把一个帧的视觉结论直接冒充另一个未检查帧的结果。

### 修改与回归：范围由影响决定

- 相机/源索引或重要相对位置有阻塞错误时优先修正，再处理接触和外观。针对本轮最大阻塞项修改，保留可回退版本；不顺手重做无关背景和动力学。
- 从出问题关键帧向前、向后检查，直到异常区间两端稳定。几何问题检查区间内全部输出帧，并在快速接触、薄壁和抓取/释放边界加密；不只修一张图，也不默认全片最细步长。
- 先让候选通过局部几何和过渡检查，再做受影响的物料模拟和最终渲染。保持四元数连续、接触约束及支撑；不要用逐帧大幅投影修正制造跳变。
- 依赖发生改变才重算：材质不使FK失效；局部杯轨迹不使静态柜体检查失效；相机变化重查相关全部投影；杯轨迹/几何变化使相关物料模拟失效。局部通过后对完整输出序列运行一次相关回归，已有缓存可复用。
- 同一种修正连续两轮没有改善时，换诊断方法、缩小自由度或登记限制。达到本轮等级且相关回归无新增阻塞问题即可停止；用户已接受的偏差不再循环修。

不能以隐藏对象、删除失败帧、独立平移视频或事后扩大容差制造通过。结果可以在既定容差内通过，不能宣称严格零相交或力学真实性已经证明。

### P5—P6：按需导出与验收

用户只要关键帧时不渲染整段；请求视频时直接导出当前已确认版本，并披露保留偏差，不为次要外观重新打开整个建模任务。全部可用视角均交付，real/sim始终保持同源索引；不为两视角数据虚构第三视角。用户需要当前未解决版本的诊断视频时也可以导出，状态应写清楚。

冻结工程与渲染配置哈希，复用同版本帧并补齐缺帧。编码后完整解码核对数量、尺寸、播放时间，抽查首末帧及抓取/落料/释放事件与源图对应；视频成功和几何/时序精度分别记录。导出阶段不重跑未失效的建模和五问基线。

交付简要说明改了什么、通过哪一级、还有哪些不影响本次交付的差异，并给直接文件链接。只有记录结构需要创建/调整时读[输出约定](references/output-contract.md)。

## 第二步：Blender → MuJoCo 场景与实际物理执行

执行本步读[迁移与接触校准](references/mujoco.md)，沿用第一步工程与接受范围。流程是：固定输入与短性能检查 → 转移结构/空腔并核对同源状态 → 分阶段物理执行 → 对准、闭合、双侧承载、力与摩擦校准 → 最终完整回归与按需渲染。

模型导入、运动学回放、基础接触、实际任务及几何验收分别记录。物体由驱动器、接触与重力推进；状态回放或抓持附着不能冒充原生任务成功。保持所有可用视角和源时间映射，五问仅增量更新受影响项。任务完成不覆盖未解决的穿入问题，第一步画面认可也不代表物理通过。

运行慢、物料/接触密集、需要恢复长跑或优化时，再读[性能与增量执行](references/mujoco-performance.md)。先短段定位成本和失败，候选有效后再跑全程；不要默认渲染每个失败候选或固定追加扰动批次。

## 控制时间与tokens

主入口只读一次；按需加载参考，优先读取摘要、问题区间和配置差异。数值扫描、候选搜索、统计、拼图、表格与视频核验交给可复用脚本；工具只返回计数、极值、失败区间和少量证据。模型集中处理新图像的空间歧义与方案选择。先看多视角总览，问题区域再放大；不要为每次微调重新加载全片图像和大段日志。

第二步先做无渲染的数值诊断和少量分阶段候选，再渲染合格模型；只保存关键帧和异常窗口的详细接触量，全程扫描返回极值、区间和实际分母。参考脚本先检查适用性；不把场景专用导出器包装成未经验证的通用转换器。输出配置变化后更新相应哈希与依赖，保留失败基线供对照。
