# 首帧：Pi3X + 语义实例 → 共享三维场景（v2）

用户选择多视角几何初始化时，在动作拟合前执行本流程。已有可靠实测标定优先保留。Pi3X、SAM 和 GPT6 的输出都是待检验估计；三套独立二维分割或来源像素回投成功不能代表多视角重建通过。

## 1. 首帧输入与 Pi3X 联合几何

取所有输入相机对应的首帧，保存源索引、相机 ID、原始尺寸及处理缩放/裁剪。已知同步关系直接使用；用户暂不考虑时间同步时明确记录同索引假设，不估计新偏移、不声称已经验证同步。缓存 Pi3X 原始相机、局部/全局点图、置信度、内参来源、版本和权重哈希。已知标定作为显式条件记录，禁止偷偷输入旧场景拟合。

近似米制尺度需用已知尺寸或机器人描述核对；无可靠锚时标 estimated。先核对 OpenCV/Blender 轴、c2w/w2c、内参恢复和像素纵横比。坐标自检只验证实现，不验证真实相机。缓存一次推理；下游 mask、mesh、纹理改动不触发无必要的重复推理。

## 2. 核心物体选择与跨视角实例

GPT6 联看所有视角，列出交互物体、桌子等支撑物、机器人/夹爪、背景柜体/椅子/显示器等可辨识物体；墙、地面等连续区域用语义区域 ID。先确定本轮需要构建的核心物体：交互物体、必要支撑、机器人，以及显著影响构图/遮挡的柜体、桌椅、显示器等。非显著杂物、人影、线缆和碎片可明确列入 excluded，不要求全量搬运背景。清单记录选择理由、必需项与省略项；不在看到失败后偷偷排除任务相关对象，也不把本场景的物体数量推广为固定配额。

- 每个物理对象分配一个全局 instance_id；同类多个杯子/椅子使用不同 ID。机器人使用全局 robot ID 及 link 子 ID，夹爪不能拆成无关物体。
- GPT6 给出语义标签及提示；SAM 用点/框等生成每张图的可见区域 mask，GPT6 检查粘连、漏分、阴影和反光误分。记录实际模型版本、提示、mask 哈希及标注来源；人工轮廓不标成 SAM，模型评分不等于审核通过。
- 用 mask 索引 Pi3X 点图得到实例点云；结合可见的跨视角投影、三维邻近、颜色/形状和遮挡顺序关联身份。SAM 的图像或视频 object ID 不自动等于跨相机全局 ID，相同颜色也不足以证明同一对象。
- 每个实例在每个视角记录 visible / partially_occluded / occluded / out_of_frame / unknown。只用真实可见 mask 评测；推断完整轮廓另存。未知身份先待复核，不强行匹配，不把遮挡像素当真值。
- 深度边缘、反光、细杆和黑色夹爪点云可能不可靠：保留置信度及冲突，不用错误点云硬约束 CAD。真实 mask 不能为了迎合模拟轮廓而自动改写。

先输出带共享 ID/颜色的多视角 mask 总览及实例清单。解决范围内核心对象未分配、误合并/误拆分和身份冲突；确认不可观测的视角不要求凭空出现 mask。

## 3. 每实例 mesh 和外观

合并已核对的实例点云，过滤离群点及重复表面；每对象共用一个局部坐标系、位姿、尺度及可渲染 mesh。GPT6 根据点云和 RGB 判断结构，选择基本体、参数曲面、深度网格或补全策略并写建模脚本；补全假设不能称为观测事实。

- **桌子先从点云初始化**：从桌子 mask 选出的点云鲁棒拟合平面、法线、可见边界和方向，估计尺寸，再投影微调。不能只有法线来自 Pi3X，却任意指定长宽或重新手调整张桌子。缺测边界不能由可见点集包围盒冒充全尺寸；桌厚、桌腿、背面缺测要标注。
- **交互物体**：点云约束可见外形，RGB 补充材质、口沿和把手等结构；容器保留空腔、薄壁和底。显示 mesh 与碰撞代理共享局部坐标，分别审计。
- **背景实例必须是完整物体**：柜体有箱体/背面，桌子有桌板/桌腿，椅子有座面/靠背/支撑，显示器有外壳/底座。每个逻辑对象有稳定 ID 和独立可编辑 mesh，可由闭合实体部件装配；允许合理补全隐藏部分，不宣称真实 CAD 或内部结构已恢复。点云用于尺寸、方向和可见边界初始化，不能仅清洗点云、连接相邻像素或做照片投影表面就称为完整物体。逐视角背景照片平面、前景烘焙残影和共享点云碎片不能作为完成证据。墙地可用有厚度的简化房间结构，不要求逐个恢复背景像素。
- **材质/纹理**：观测纹理排除遮挡并融合曝光，先核对颜色空间与灯光。捕获 RGB 含光照，不直接称为纯 albedo 或任意重光照资产。逐相机背景平面不能替代共享三维场景。

记录 observed / fitted / completed 部分。隐藏点云不等于背景建模，杯碗通过不等于全场景通过。

## 4. 机器人用 URDF/XML 初始化并对齐

实际导入 vendor URDF/Xacro 生成物或核验过的等效 XML 和 CAD，检查 visual/collision origin、axis、limit、mimic、工具与传感器安装、完整 link 层级及 FK。文件在磁盘上不等于机器人已导入。

用多视角机器人 mask/可辨识关键点、可靠点云及场景关系拟合基座、关节初态、工具/手眼待标定量；固定可信尺寸、关节链和实测量。腕部相机由 FK × 固定手眼描述。禁止逐 link 任意缩放或用不合理相机安装距离补二维偏差。隐藏姿态标估计；单帧不足时补静态观测或后续运动帧用于标定，不能谎称已辨识，也不因此提前运行物理任务。

## 5. 共享场景的多视角投影迭代

先低分辨率渲染实例 ID/depth，逐实例×视角核对可见区域 mask IoU、轮廓/中心误差、深度顺序、漏失和合并；按投影尺寸归一化误差。不能让大背景平均分掩盖夹爪/杯子错误，容差依用途预先记录。

先冻结可信相机，优化同一 mesh 的位置、姿态、尺寸和必要形状参数。多个对象出现同方向系统偏差时检查相机，再做有先验的联合标定；相机、尺度和几何不能同时无约束漂移。保留支撑、刚体形状和已知尺寸约束。

独立真实 mask + 可见跨视角重投影作为证据；点云回投来源像素仅是坐标检查。可用的静态留出帧另做验证；缺少独立证据或可观测性不足需如实记录。遮挡和重复纹理等冲突不能靠提高阈值关闭。

数值拟合只生成候选，不自动验收。完整对象加入共同场景后重新渲染可见 ID，检查实际遮挡；独立对象凸包投影的 IoU 不能替代这一结果。双视角优化记录各视角的得失，不只汇报提高的一侧；省略遮挡杂物后暴露的 sim 表面应与形状残差分开解释，真实 mask 不随 sim 修改。

先做完整场景的结构审计，再检查同相机、同几何的灰模和 RGB。统一灰模不能隐藏问题对象或改变相机，临时替换材质须保存并恢复面材质索引；交付图须可由保存的工程重现。增加一个新观察方向或逐物体预览，以验证背面/厚度/支撑确实存在。逐视角回答五问：①最大差异；②相机；③相对位置；④穿模与接触；⑤材质/纹理/光照/背景。mask 几何验收不替代第五问。未变实例复用缓存；局部修改重查相关遮挡/接触；公共相机或尺度改变则重查所有受影响实例。

## 6. 门槛与证据

顺序：**共享实例与语义 → 每实例点云/mesh → 机器人结构和位姿 → 首帧完整场景投影及五问 → 动作拟合和事件邻域五问 → MuJoCo 原生物理 → 物理轨迹回传 Blender 验证**。可先做静态支撑/穿入和 FK 诊断，它们不等于完整物理执行。修正持续累计，不设次数上限。

首帧列入 required_frames，检查所有输入视角，不替代交互事件。静态交付包含共享相机/尺度、实例清单、可编辑 mesh、机器人描述与初态/手眼来源、RGB/灰模对照、静态审计、逐视角五问和接受范围；下一步从真实视频恢复动作，不直接把静态场景当成运动已完成。实例、机器人、背景或相机未过时保留 not_started_alignment_gate，不能靠杯碗子项通过推进阶段。

review_gate.json 中设置 initial_alignment，包含 required=true、method="Pi3X+semantic_instances"、mode="instance_first"、frame=0、status、evidence/evidence_sha256 及 instance_manifest/instance_manifest_sha256。清单路径相对 gate，清单内路径相对清单目录。check_review_gate.py 校验下面的覆盖和证据，再执行通常五问门槛；脚本不会自动判断图像质量。

实例清单最少包含：

- views、inventory_reviewed、unassigned_visible_regions、instances；总览 inventory_evidence/inventory_evidence_sha256。无法辨识区域保留 unknown，不隐式算通过。
- 每实例 id、semantic_label、role（interaction/support/robot/background）、identity_status、geometry_status、observations，以及 mesh_path/mesh_sha256。
- observations 以全部 view ID 为键：visibility、status；可见或部分遮挡时含 mask_path/mask_sha256/mask_source；不可见时含 reason。
- 非机器人含 cloud_path/cloud_sha256/geometry_source；无可靠点云时注明 cloud_unavailable_reason 和替代依据。机器人含 description_path/description_sha256/structure_status/alignment_status、结构审核 structure_evidence/structure_evidence_sha256。
- 仍在构建中的 mask/mesh 允许为空且状态 pending；review 可记录未完成候选，进入物理/合格交付必须补齐文件、哈希和通过状态。已声明的文件在任何阶段均核对哈希。

实现依据：[Pi3X](https://github.com/yyfz/Pi3)、[SAM 2 官方图像/视频分割](https://github.com/facebookresearch/sam2)。执行前检查版本、设备、权重；未安装或未运行只能标 pending，不伪称已有分割输出。

## 7. 结构审计与增量成本

- 在完整场景中检查支撑接地、法线朝向、开边/非流形边、容器空腔和机械链。扩大审计到隐藏桌腿、估计支架、工具和传感器安装件；只测桌板与杯碗会漏掉隐藏穿插。部件有意搭接与不同物体的非预期穿入分开记录。
- BVH 三角形相交可能是支撑面共面接触；结合法向、支撑关系和有符号间隙分类，别仅以相交对数量判失败。无表面相交也不能排除完整包含或证明动态无碰撞；原生物理另验。
- 已知机器人基座/关节链不为背景拟合而改写。估计支撑出现冲突时优先在合理范围调整支撑或背景位姿，重新检查承托、完整性与投影；不是把冲突部分隐藏。
- Pi3 推理缓存一次，实例点云/真实 mask 按版本复用。先低分辨率多视角参数拟合和静态审计，定位到对象后再看局部放大；本次接受的静态材质与背景进入动作阶段保持不变。
- 不把场景专用脚本、数量、尺寸、颜色、相机 ID 或某次 IoU 当通用算法/阈值。新模型必须从其真实输入取证。
