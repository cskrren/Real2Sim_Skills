# 接触面、释放与交付排查（v3.3）

第二步第3/6环节换末端、接触校准，或第7/8环节遇到数值与画面不一致时读取。来自 EgoDex 1338 四硬件执行经验；案例的落点偏移、增益、时间缩放和穿入容差不能直接迁移。适用于 robot/human 输入，实测状态保留原件，适配轨迹单列。

## 第3/4环节：从接触面生成可执行参考

- TCP/site 是参考点，未必是指垫。按实际 collision geom 类型处理 mesh、box、capsule 等，核对局部变换、半径、朝向与可承载面；只在类型确为 mesh 时访问 mesh 索引，避免负索引误读其他资产。
- 对准位置之外，检查两侧接触法向与目标厚度。正面推压把手即使有力也未必能拉动抽屉；灵巧手应拟合对向指垫，而不是仅拟合指尖 site。
- 同时规划非抓持手指、掌面、另一机械臂的避让。检查关键姿态之间的插值，快速接触/释放段加密 FK、关节限位和碰撞检查；IK 到自建目标的低误差不能替代真实图像复核。
- 对轴对称平行夹爪，可比较保持接触语义的等价朝向以避开腕关节限位；不把对称性假设用于非对称灵巧手或工具。

## 第6环节：持物与释放分开校准

1. 保持“对准与角度 → 实际闭合 → 双侧持续承载及滑移 → 力与摩擦”的顺序。记录命令和实际关节/开口；必要的预载以控制目标实现，核对关节与驱动器限幅，不能修改资产尺寸或无限提高力来强行抓住。
2. 稳定窗口分别统计两侧承载、持续比例和滑移。两侧都有正力不自动构成对向夹持；检查法向、力方向与对象运动。首触、搬运和释放窗口分开报告，保留实际步数分母。
3. 抓住之后仍可能放不下：按实际接触对定位非抓持手指、掌面、容器上沿、隔板、其他把手导致的拖拽/倾翻。先改释放路径、姿态和手指退出次序，再考虑动力学参数；落点偏移须保持真实任务关系并更新受影响关键帧五问。
4. 放置验收看完整物体形状、方向及关闭路径间隙，不只看质心。侧翻物体可能已“进抽屉”但挡住闭合；分开检查包含、稳定支撑、释放后速度和机构最终位置。不要通过放大容器、缩小物体或屏蔽真实障碍制造成功。
5. 确有软接触穿入时，检查实际接触对生效的求解参数、优先级、步长和稳定性，再做受控调整。接触参数改善不证明质量/摩擦已辨识，也不能掩盖错位。刚体替代软玩具时明确形变能力缺失。

## 第7环节：诊断证据与最终证据

- 局部候选先用短段区分假设，再验证前后稳定边界。仅从 qpos 恢复、清零速度的探针是近似诊断；即使成功，也不能称为精确续跑或完整任务通过。完整状态恢复要求见[性能与增量执行](mujoco-performance.md)。
- 极端距离值先保存原始 geom 对、类型、变换和同一时刻状态。结合接触记录、几何可视化及适用的独立几何计算交叉核对；盒体可用 OBB SAT，但其结论不能推广到任意网格。不能直接裁剪负值或删除离群步。若修正审计方法，对最终整段重新审计并保留旧结论及原因。
- 最终模型、控制、资产与初态从磁盘完整执行；任务、几何、数值警告和视觉各自判定。仅当恢复逻辑或审计异常需要解释时增加同配置复验，比较模型/控制哈希与原生状态差异；无变化且已通过时不反复复验。
- 多硬件共用输入、接受的场景、事件和相机；安装、IK、接触控制及验收分别记录。分别校准后的成功案例不能作为同控制器的公平硬件性能排名。

## 第8环节：同一原生轨迹驱动两种渲染

- 绑定稳定对象 ID，处理对象局部坐标、mesh origin、父级与相机变换。对全部交付帧自动检查 Blender 求值变换与本次原生状态、源相机一致；纯碰撞代理等例外逐项列明。这是数值绑定检查，不要求全部帧重新写五问。
- 有实测相机优先保留；人体 ego 相机独立于替代机器人。真实腕部相机才按对应机械链与安装关系运动。物理时间缩放、源帧映射和播放 fps 单列，额外稳定等待不混入有真实对应的帧。
- 按[外观规范](rendering.md)覆盖前景、支撑和核心背景。按对象选择合适的 PBR、程序纹理或生成适配，记录实际来源；不为了使用生成工具而增加无证据纹理，不将程序纹理宣称为下载或生成资产。特定网格的法线修改器崩溃时局部回退并复核，不重做物理。
- 完整重开最终 blend，核对同轨迹/相机绑定，再编码并完整解码。页面、五问、任务结果和视频从同一候选记录生成；哈希覆盖实际资产与控制入口，检查链接有效。脚本若依赖所在目录，应写明真正运行入口，不把快照目录声称为可独立运行包。

## 减少无效计算与 tokens

共享静态资产和真实事件，按硬件缓存适配结果；每轮只读当前候选差异、失败接触对和短窗口。数值筛选后渲染少量诊断图，合格候选再全片渲染。五问保留逐关键帧覆盖，未失效项引用原证据；日志返回极值、区间和分母。维护统一候选记录，避免分别手改页面、汇总和验收状态。案例脚本只有去除硬编码并验证适用范围后才可作为通用工具。
