# 事件驱动关键帧、邻域五问与物理判定

P0/P4 与第二步评测共用本规则。先独立观察真实视频的关系变化，再与重建/物理事件对比。仓库示例图、已有脚本中的帧号、均匀采样帧只能作为 `context` 或检索候选，不能直接成为完整的交互关键帧集。

## 1. 什么是事件与 key frame

**交互事件**是两个或多个逻辑对象之间关系的建立、解除或功能改变。对象是夹指、工具、杯、物料、支撑面等有物理意义的实体，不是网格三角形或碰撞接触点。杯底接触点增加不算新事件；桌面支撑转为夹爪承载，即使某些接触对仍存在，也算事件。

|关系变化|取帧依据|
|新接触 / 分离|同一对象对从可辨认的间隙到触碰，或从触碰到完全分离；再次接触另记事件|
|抓取建立 / 松开|单侧接近、首触、双侧夹持与持物稳定分别记录；不能仅以闭合指令判定抓住|
|支撑转移|离桌、离架、落桌、落入容器后被底部/其他物体承托；区分首次碰撞和稳定支撑|
|进入 / 离开 / 插入|物体相对容器边界或插槽的关系变化；越过杯口、撞杯壁和最后落定可以是不同事件|
|操作改变|滑动开始、卡住、脱落、装配锁止等任务相关变化；视觉无法判断锁止时保留未知|
|异常交互|意外碰撞、单侧丢失、滑脱、穿入、结构断裂、跳变；无论参考图是否包含都要检查|

**关键帧是事件证据窗口中的带角色源帧**，不是固定数量的漂亮截图。每个事件至少覆盖：

- `before`：关系尚未改变的最近可辨认状态。
- `onset`：首次观察到变化的帧；若被遮挡或采样太稀，只能记录 `[last_old, first_new]` 区间，不能制造精确首触帧。
- `after`：新关系建立并稳定、或已经明确失败的状态。短暂碰撞未稳定就分离时，如实保留短事件和分离帧。

起止帧、最大倾角、纯外观留出帧可额外保留为 `context / extrema / holdout`，不计入已覆盖交互事件的分母。多个事件共用同一源帧时复用图像并保留所有事件 ID。物料密集时可按一次落料批次展示，但检测保留粒子/对象明细、数量分母、意外碰撞与最差个体，不能聚合掉异常。

## 2. 从视频发现，向事件附近加密

1. 在建模前浏览各视角全片，建立对象表和关系时间线。可先用低分辨率视频、跟踪或接近度筛候选；固定间隔截图只用于找候选，不能单独证明没有遗漏短暂接触。记录实际扫描的视角、帧范围、步长和盲区。
2. 在候选周围按原始帧加密，寻找 `before/onset/after`。邻域由关系变化决定，不固定为前后 5 帧或 1 秒；先小窗口，边界尚在变化就继续扩展至稳定状态。快速运动或低帧率数据无法定位中间首触时保留采样不确定性。
3. 每个真实事件记录 `objects / relation_before / relation_after / source_indices_by_view / real_time_interval / visibility / confidence / evidence`。显示名称不能决定相机身份；必要时核对源元数据。无法观测的接触可提出假设，但不标为真实测量。
4. Blender/MuJoCo 运行后独立提取模拟事件，保存物理时间与源时间映射。匹配的是对象和事件语义，不能以模拟事件反过来定义真实首触。
5. 评测帧集取**真实事件邻域、模拟事件邻域、异常区间**的并集。真实与模拟事件早晚不同，两处都取同源时间的 real/sim 对照，并报告时间差；不能把真实首触与另一时刻模拟首触拼成“同帧对齐”。未找到对应事件也要报告。
6. 修改后重新检测受影响对象的事件，新出现的接触或异常补入并集。消失的真实事件仍是待匹配项，不能被候选覆盖掉。新增检查帧不重置迭代次数。

## 3. 全场景审计先于五问

首次建模先检查所有任务相关对象的尺度、结构连接、杯底/薄壁/空腔、初始支撑和初始相交；记录显示网格与碰撞代理差异。检查机器人机械链、夹爪安装和关节范围。背景固定件可按用途固定，不能把活动目标固定来伪造稳定。

同时做全序列低成本运动/碰撞筛查；关键事件窗口再加密。只查起始帧不足以发现中途断裂、跳变或穿透。旧场景的结构结果只能在续做且依赖未变时复用，`fresh_start` 不复用旧资产检查。

## 4. 事件邻域的五问

对选定的每个 `before/onset/after` 帧、每个可用视角都保留五问。共用同帧只存一次，多事件引用；首次没有看过的帧不能继承邻帧视觉结论。向前后扩展新增的检查帧同样列五问，数值逐步扫描的所有中间状态不必逐条写长文。

|问题|事件前 → 事件时 → 事件后|
|① 最大差异是什么？|接近路径 → 首触部位/时间 → 抓持、落点或支撑结果；写当前帧的主要差异及影响，不默认失败|
|② 同帧相机视角是否对齐？|核对相机与源索引、静态锚点 → 接触区投影 → 腕部机械链运动；先排除索引、内外参错误|
|③ 物体相对位置是否一致？|间隙与方向 → 夹持位置/角度、对象次序 → 遮挡、相对工具姿态、支撑/包含关系|
|④ 是否存在穿模或不合理接触？|初始间隙/支撑 → 接触面和碰撞代理 → 滑移、穿透、异常分离；RGB遮挡与三维穿入分开|
|⑤ 逼真度是否足够还原？|形状、材质、纹理、背景 → 接触处轮廓、阴影 → 动作与任务结果是否清晰；按用途，不无限追求照片级|

执行优先级是**源时间/相机 → 相对位置 → 穿模/接触 → 外观**。①为观察项。②③出错时先修正，再解释④的画面差异；已由引擎确认的数值异常仍保留。每问保存一句帧特定观察、证据、状态与是否阻塞；可用 `pass / pass_with_notes / fail / review / not_evaluated`。不可见项引用其他视角或引擎证据，但不能把模拟证据写成真实接触真值。关键必需项仍未知时不能汇总成全通过。

## 5. 物理引擎层面的独立判定

以下是项目验收规则，不是所有场景通用的数值阈值。基线前记录单位、目标尺度、穿入容差、接触力门槛、保持时长、滑移/速度限值及理由；不在看到失败后放宽阈值。

|层面|判据与必要证据|
|结构与初态|有限且合理的质量/惯量、自由度、尺度；连接、空腔和支撑合理；初态无超容差相交；装配排除对有来源|
|接触建立/解除|按逻辑对象对聚合有符号距离和求解得到的法向力，保留左右夹指分别统计；用滞回及保持时间避免把接触点抖动算成新事件|
|对准与闭合|接触参考点/夹爪轴相对目标的位置和角度，命令与实际开口，碰撞面厚度、mimic、限幅；不默认杯中心等于抓取中心|
|稳定抓持|双侧有效接触/承载的持续时间和占比，目标相对工具平移/转动滑移，离开原支撑后的持物；非双指机构改用对应承载定义|
|穿入与隧穿|已检测碰撞对的 `max(0, -distance)`、对象对、位置、持续时间和最大值；同时核对漏掉的碰撞对、显示/代理偏差、薄壁穿越；不能只看接触列表为空|
|力与控制|实际驱动力/力矩、饱和时长、指面力与滑移，参数生效值；先对准和双侧接触，再校准增益/摩擦/抓持力|
|支撑与包含|支撑力按对象—支撑关系聚合并考虑方向；整体形状在容器内、边缘碰撞、释放后独立支撑；中心点进入不等于整体进入|
|运动与稳定|实际任务完成、速度/加速度及关节约束、平移和转动末态稳定；物料保留数量/逸出/落入分母；没有状态重置或附着伪造持物|
|数值可靠性|每步有限状态、警告、约束误差、实际步数/时长、步长及求解配置；必要时针对薄壁/快速碰撞减小步长或连续几何检查|

MuJoCo 实施要点：接触可能在正间隙的 margin 内产生，也可能被检测但未产生约束力。用求解后的 `mj_contactForce` 读取接触坐标系下的力/矩；转到世界坐标并按受力对象统一符号后才能判断支撑方向。不能仅用 `ncon>0`、`dist<=0` 或把所有接触力相加来宣布抓住。见官方[接触模型](https://mujoco.readthedocs.io/en/stable/computation/index.html#contact)与[力读取接口](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mj-contactforce)；实施时核对安装版本。

状态、接触与力必须来自同一物理时刻；避免积分后 qpos 搭配上一步接触。回放中仅调用几何/前向求解可以诊断接触，不能替代驱动器推进的原生任务执行。软接触下在事先容差内的微小穿入不自动等于失败；超限、隧穿或视觉网格明显穿透不能因任务返回成功而忽略。

扫描覆盖完整相关物理步序列（保存摘要，详细量仅保留事件/异常窗口）。按任务要求对高风险对象补几何检测；报告离散采样步长和盲区，不能声称严格连续无穿透保证。对 Blender 第一阶段只能报告几何、运动和可见接触合理性；未执行 MuJoCo 的物理力学项写 `not_evaluated`。

## 6. 覆盖门槛与最多 5 轮闭环

至少保存事件覆盖表：`event_id / origin(real,sim,anomaly) / objects / time_interval / matched_event_id / before,onset,after / views / five_question_record_ids / physics_evidence / unresolved`。

交付分别汇总真实事件发现范围、已发现事件数、匹配/未匹配/未知数、事件邻域完整数、五问实际已检查帧×视角数、物理实际扫描步数。`已发现事件覆盖率`不等于证明全片所有真实接触已被发现；缺少候选扫描和遮挡说明时不能声称完整。

在当前验收范围内，缺失真实新接触、未查事件邻域、相机/相对位置阻塞错误、超限碰撞或任务失败均不能被参考帧好看覆盖。修正按主入口的**每场景两步共用最多 5 轮**执行：定位 → 改候选 → 向前后扩查至稳定边界 → 受影响事件再检测 → 五问与物理回归。最终从磁盘最佳候选做完整相关回归。达限则明确未解决项；视频按需导出并标明状态。
