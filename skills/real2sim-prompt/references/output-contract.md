# 输出与评测记录约定

沿用现有兼容目录，不为接入技能迁移数据。新增或调整记录时才读取本文件。

## 最小可交付记录

- 场景和资产版本、坐标单位、相机身份、真实状态/估计/插值/模拟的来源。
- 源帧、各视角源索引/时间戳、Blender帧、视频帧映射；硬件同步未知则明确未知。
- 工程文件、所需视角real/sim图像、交互事件和逐关键帧五问；视频按用户请求导出。
- 一份交付清单指向场景、配置、评测及输出哈希。深度、实例分割等仅在任务要求时生成。

## 质量与接受范围

`acceptance_profile`采用`usable_reconstruction / precise_alignment / high_fidelity`。

分别记录：`technical_observation`（观测或数值）、`status`（当前用途下的判断）、`blocking`、`acceptance_basis`（用户接受或证据）、`known_deviations`。用户接受时保存原话/范围和场景哈希，保留历史评测，不篡改原始误差。

状态：`pass / pass_with_notes / fail / review`。最大差异描述可为`observed`；未检查项写`not_evaluated`，不能伪装为技术通过。任务相关的阻塞项计入失败分母；观察项、已接受偏差和遮挡未知分别统计，不将其全部加成“失败率”。

用户认可当前重建画面可使其在当前用途下通过，不代表未知接触力、精确三维或严格时序已认证。项目的一次接受不自动构成后续项目的通用容差。

## 事件与五问

事件保存对象关系前后状态、真实/仿真代表帧或时间窗口、前后证据、来源及遮挡不确定性。源索引不重排；图像不可观测的首触时刻记未知。

每个关键帧×视角一条记录，五问均保留：

`largest_difference / camera_alignment / relative_object_alignment / penetration_and_contact / reconstruction_fidelity`

每问含状态、一句针对当前帧的观察、证据和是否阻塞。相机/几何共享证据引用文件或记录ID，避免重复长段解释。局部更新可用`inherited_from`引用依赖仍有效的既有结论；保存当前修改项与受影响问题，报告生成器展开完整表格。未看过的帧不能用邻帧结论代填。

## 几何与区间

全场景首次审计记录对象/碰撞代理、结构、支撑及排除对。增量审计记录检查范围、被修改的依赖、复用的基线及理由。

问题区间记录异常首末帧、前后稳定边界、修正内容、输出帧与子帧步长、实际样本数、最大深度/间隙、失败与待复核样本。无连续检测时不宣称连续保证。严格零相交和容差内通过分开表述。

## 导出核验与报告

视频记录工程/渲染哈希、相机顺序、源帧映射、尺寸、帧数、播放时间及编码。完整解码，抽查首末帧、修复区间和关键事件与源图对应。

最终摘要只展示本轮改动、当前验收等级、已通过范围、阻塞问题、已接受偏差及产物链接。完整数据留文件；不要把历史严格评测的fail未经解释当作用户认可版本的当前结论，也不要删除历史记录。

## 第二步：MuJoCo 物理执行记录

仅本步需要新增这些记录；允许现有文件承载，不强制每个字段独占文件。

- **输入与复现**：源 `.blend`、MJCF、显示/碰撞资产、机器人描述、初始 keyframe、控制轨迹/策略、物理参数及版本哈希。共享资产路径可解析；磁盘最终模型可独立初始化运行。
- **参数来源与差异**：质量/惯量/摩擦/驱动的 `measured / asset_nominal / estimated / calibrated` 来源；校准前后值、单位、修改理由、保留的实测记录及辅助约束（如有）。仿真调优值不能改标成实测。
- **分层状态**：`model_import / kinematic_replay / contact_tests / native_task` 分别记录 `pass / pass_with_notes / fail / not_evaluated`。保存 `execution_mode`（如状态回放、驱动器物理执行或辅助执行），禁止汇总成无法区分的单一“成功”。
- **物理事件与关键帧**：实际物理时间、源索引、对准偏差、闭合目标/实际值、各侧接触对及法向力、双侧承载定义与时长/占比、相对工具滑移、释放及最终支撑。五问只更新被物理运动影响的项，共享接触证据可引用。
- **完整回归**：真实物理步长、步数/时长、检查区间、最大穿入、力峰及中位数、驱动力矩峰值、求解器警告、物体整体到达目标与最终速度；标明坐标一致性误差是在比较 Blender 还是实测数据。
- **扰动与验收**：标称结果、每个扰动配置和结果、真实分母、既定容差、未解决项。初触过渡、短暂力波动、状态缺测不能被改成严格零误差或百分之百稳定。
- **视频与入口**：注明渲染来自哪次原生状态序列，区分回放、实际执行和失败诊断视频；源范围与额外稳定时段分开记录。最终清单指向当前模型、控制、报告与视频，旧失败证据保留并标注版本。

### 第二步状态与性能摘要

任务结果与几何/数值状态分别记录；总体状态综合本轮必需检查。成功返回值和退出码不能覆盖超容差项。支撑力按物体—支撑关系聚合，两侧夹爪力分别汇总；保留接触点数与汇总方式以避免阈值误判。

性能记录包含相同模型/配置标识、阶段、实际步数、物理时间、墙钟耗时及代表性接触规模。非隔离的前后运行不声称单变量因果。候选提前结束记录原因、已覆盖范围及可恢复状态位置，不把未执行的剩余阶段标通过。

## 标定、显示与精细渲染记录

允许现有清单承载，不强制新增多份文件：

- **对齐证据**：拟合/留出观测ID、视角、分辨率、观测点数、重投影误差、先验和已知畸变/不可观测项。共同拟合与独立验证分开。
- **外观完成度**：主要对象材质类别、纹理来源/尺度、背景补全项、灯光与色彩管理、已接受残差；区分 `diagnostic_preview / blender_reconstruction / blender_native_physics` 图像用途。
- **回传绑定**：显示对象与物理 body/link 的映射、局部偏置、轨迹来源/哈希、采样/插值、各视角时间映射、求值变换误差及重开工程复核结果。
- **可复现渲染**：显示工程、外部资产、相机、引擎/版本/设备、样本/降噪、输出尺寸/像素比例、图像与原生轨迹哈希；记录已检查的样帧与未检查项。缺失资源不得静默回退后仍标为精细渲染通过。
- **试验假设**：校准目的、改变变量、预期/实测响应、实际生效参数和接受/拒绝理由；敏感性试验不写成已完成物理辨识。
