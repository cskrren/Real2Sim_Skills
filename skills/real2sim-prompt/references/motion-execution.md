# 第二步：从静态场景到动作与原生物理

第一步首帧已接受、需要恢复视频动作或进入 MuJoCo 时读取。仅解释下一步或整理 skill 时不自动启动重建、训练、完整物理或视频渲染。

## 1. 接收已接受的静态场景

读取接受记录、工程/配置哈希、源 RGB 与索引、机器人描述、相机/手眼和交互实例。区分“有静态场景”“有运动目标”“有原生 rollout”；首帧成功只完成第一项。保持已接受的核心背景与可信尺度，不重新推理 Pi3 或重建背景。用户暂不考虑时间同步时沿用已记录的帧对应假设。

## 2. 从真实视频恢复事件与运动参考

先浏览真实视频，发现物体之间接触、抓持、支撑、包含的建立/解除/改变，为每个事件保留 before / onset（或区间）/ after。仓库参考帧、均匀抽帧仅补上下文，细则见 [事件与复核](events-and-review.md)。

沿用首帧全局实例 ID，在各视角跟踪真实可见 mask/关键点；SAM 视频传播提供二维轨迹，跨相机/跨时间身份由共享几何与可见性联合核对，遮挡处保留不确定性。用多视角投影恢复目标物、末端的连续位姿和夹爪开合。有关节实测时优先使用并核对 FK；仅 RGB 时固定真实关节链与可信尺寸，以 IK/轨迹拟合估计关节目标，腕部相机由机械链与固定手眼共同运动。

输出源帧映射、真实事件表、物体/末端/关节及开合的参考序列、来源和置信度。优化的 3D 自建目标到达误差不能代替真实 RGB 对齐；保留未参与拟合的可用帧。

## 3. 先检验动作是否匹配真实观察

用 Blender 低成本预览检查事件邻域的所有视角，每帧完整回答五问：最大差异、相机对齐、相对位置、穿模/接触、逼真度。相机/目标/夹爪位置先对，再看控制和摩擦。发现问题向前后扩查到稳定边界；相机或手眼改动使相关投影失效，局部轨迹改动不使无关背景失效。

运动学轨迹是控制参考或诊断，不是物体已被物理抓住。目标物的实测/拟合位姿可用于比较，不能在原生任务中逐帧强制设置其状态来冒充接触成功。无需先渲染整段精细视频才开始短物理诊断。

## 4. MuJoCo 装配与分段接触执行

按 [迁移与接触校准](mujoco.md)导出 URDF/XML 结构、初态、目标和碰撞几何，容器保留可碰撞空腔。记录质量、惯量、摩擦、驱动限制及来源。显示网格可完整保留在 Blender；静态远背景不必全部进入昂贵碰撞，依据可达域、支撑与任务路径决定，不能移除真实会接触的实体。

先静置/支撑，再接近 → 首触 → 闭合 → 持续双侧承载 → 搬运/任务动作 → 释放/落定。抓取失败依次检查 **对准位置和角度 → 实际闭合量 → 双侧接触及滑移 → 力、力矩、摩擦**。采用合适的关节/末端控制，Mink 只是 IK 选项。目标由重力和接触推进；辅助约束、附着和状态回放必须单列，不能称为原生成功。

## 5. 验收与回传渲染

独立记录导入/FK、基础接触、物理任务成功、穿入/数值稳定及同源视觉对齐。最终磁盘模型/初态/控制做完整相关回归；再将原生机器人、目标和物料状态回传原 Blender 显示场景，保留材质与核心背景。腕部相机跟随原生机械链。

只要关键帧就输出事件对照；用户要视频再导出全部可用视角的逐帧对应 real RGB / sim RGB，实际解码检查帧数和索引。静态阶段接受的近似不自动否决动作；若运动显露未知区域或进入其接触范围，才重新打开该问题。

省成本的执行顺序：缓存静态阶段 → 一次真实事件/轨迹提取 → 少量局部运动预览 → 无渲染短物理诊断 → 合格候选完整回归 → 一次最终渲染。失败窗口按需展开，不每轮扫描大日志、重写全文五问或渲染整片。
