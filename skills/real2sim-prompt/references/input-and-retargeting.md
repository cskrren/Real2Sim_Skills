# Robot / Human 输入与目标机器人

在第一步接收输入时确定分支；第二步第 3 环节执行该分支。只有 human 输入或更换机器人形态时才加载重定向细节，robot 同硬件回放不额外启动人体重建。

## 入口契约

记录以下字段，缺失项写 unknown / unavailable 及处理方法，不以默认值冒充测量：

- `source_actor_type`: robot / human；混合视频按实例分别记录来源与操作角色。
- `source_views`, `source_frame_indices`, `timestamps`, `intrinsics`, `camera_poses`：单视角、多视角均可；只有一个真实视角就只验收该真实视角。新建观察相机单列为 sim-only。
- `source_state`: 机器人关节/末端/开合，或人体腕、指尖、手部姿态与置信度；RGB-only 允许估计并标记不确定性。
- `target_robot`: 硬件名称、URDF/MJCF 与网格来源/哈希、关节链/限位、工具安装、TCP 定义、左右臂与末端配置。明确厂商模型和自定义代理，不能将自制平行夹爪标成已标定的 Robotiq。
- `target_selection`: 用户指定/沿用已接受配置/按任务选择的依据；比较多个目标时记录独立 candidate ID、配置与输出路径。
- `transfer_mode`: same_robot_reconstruction / robot_to_robot / human_to_robot；`arm_roles` 记录各臂 active / support / idle。
- `source_to_robot_transform`, `scale_source`, `time_mapping`, `generated_extension`：坐标、尺度、时间及无真实对应的补充控制。

先看 RGB 确认实际事件与片段完整性，不能把数据集的整段任务标签当成本片段已展示的动作。切换场景时保留候选/筛选规则和原因，不将任务适配筛选宣称为全体 valid scenes 的均匀随机抽样。

## 第一步：目标机器人与静态初态

**robot 输入**：优先用源硬件描述和实测关节初始化；更换硬件时另外建立目标机器人，保存源机器人参考，不覆盖实测状态。

**human 输入**：人体是动作示范者，目标机器人是新选择的执行体。先重建共享桌面、交互物体与核心背景，再按可达域、操作空间和任务接触需求配置机器人基座、工具、夹爪初态；不把人体骨骼长度直接缩放为机械臂。v3.3 支持显式选择目标机械臂与末端，按[目标机械臂选择与适配](target-robot-selection.md)确定单/双臂、夹爪/灵巧手及实际资产版本。双 FR3 + Franka Hand 原装夹爪作为本项目第一种配置，可作简单抓放的起点，不是所有视频的固定要求。独立指尖接触、手内旋转或密集薄物体等任务需单独判定平行夹爪能力，不靠增加摩擦掩盖不兼容。

robot/human 两分支共同遵守[几何初始化](geometry-initialization.md)：单视角首帧使用 MoGe-3，多相机首帧用 Pi3X；mesh 以首帧 RGB 为主、仅首帧点云为辅，并用不超过10个后续重要稀疏 RGB 帧补全与投影校正；后续不新增参考点云。

人体摄像机保留独立的真实相机轨迹；只有确有安装关系证据时才成为机器人的腕部相机。标定、已知尺寸与接触平面作为几何约束；MoGe-3/Pi3X 未运行须明确标记，不以这些约束冒充已完成模型推理。

## 第二步第 3 环节：恢复运动参考与跨形态重定向

### robot 分支

同一硬件且有实测关节：复用关节序列、时间戳与开合，并用 FK 对照 RGB。没有关节：根据视觉末端/物体轨迹与真实 URDF 链估计 IK。更换机器人：将源末端/TCP 与对象相对轨迹映射到目标硬件，执行可达性和避碰检查；源关节数值不能直接复制到另一种机器人。

### human 分支

1. 从真实 RGB 与可用人体状态恢复手/指尖、物体及接触关系。指尖中点可作为两指夹持中心初值，须同时估计夹持轴、进场方向、接触面与开合量；腕位置和指尖距离都不能直接等同于机器人 TCP 与夹爪命令。
2. 在物体坐标系定义接近、抓持、搬运、落点等目标，保留人体运动参考及不确定区间。由重建尺度与坐标变换进入机器人工作空间，不能无记录归一化或任意放大物体来制造可达。
3. 用目标机器人关节链与工具/TCP 偏置，联合拟合位置、方向、限位、平滑性、可达域及机器人—物体/环境/另一臂避碰。双臂按真实任务分工协调；仅一手动作时另一臂可静止，不能据此宣称验证了双臂协作。
4. 输出目标关节/末端/开合参考，记录接触停留、避碰绕行、时间缩放等适配。机器人到自建目标的 IK 误差只证明目标可达，不能代替真实图像、事件和物体相对运动的对齐。

这是运动参考，尚不是实际抓取。转入第 4 环节五问及问题邻域复核，合格后再进入第 5–7 环节的模型装配、接触执行和回归。

## 共用验收与输出

- 五问保持不变：最大差异、相机、相对位置、穿模/接触、逼真度。human_to_robot 中，机器人与人体轮廓不同是明确的替换结果；核心验收是物体布局、任务接触/支撑关系、运动目标与视角，仍需检查机器人过度遮挡、穿模、绕行和事件滞后。不能把所有替换差异自动豁免。
- 源事件和模拟事件各自记录。接触不清楚时保留 onset 区间；帧数少、片段被截断或缺少释放结果，不补写真实成功。
- 时间缩放记录 `source_frame/source_time -> sim_time`，同源对照不等于物理速度相同。补充的释放/静置/复位没有真实帧，单独展示并标记，不能复制真实末帧伪装同步。
- 两分支的物理成功均依赖原生驱动、接触、任务结果与稳定性；Blender 动画、FK 回放、附着/weld 或退出码不替代原生任务证据。
- 第 8 环节共用同一原生状态序列驱动 Blender 与 MuJoCo，输出 Real RGB / Blender RGB / MuJoCo RGB。人体输入的 Real RGB 保留人手；模拟列为目标机器人。前景、支撑物和已选核心背景都要有外观处理与残留差异记录。
- 报告分开写静态初始化、动作参考、原生任务、外观、时序、双臂协作各自状态。功能可用不等于照片级；一个 human 场景成功不构成 robot/human 全任务通用性的实测证明。
